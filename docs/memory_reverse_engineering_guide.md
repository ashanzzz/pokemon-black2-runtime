本文档记录基于 BizHawk Lua TCP Bridge 在真实硬件总线与 Main RAM 中逆向得出的核心数据结构、内存地址、偏移规则与拓扑数学关系。

## 零、 标题与主菜单/初始界面内存结构 (`0x0223B630 ~ 0x0223B639`)

在游戏未载入 Overworld 大地图时（如游戏启动、标题界面、主菜单存档选择），系统通过该结构体维护菜单项与用户光标选择：

```text
ARM9 物理地址       偏移量 (Offset)    类型           物理含义与逆向结论
---------------------------------------------------------------------------------------------
0x0223B630..34     +0x00 ~ +0x04     uint8[5]       【当前菜单选项 ID 列表】
0x0223B639         +0x09             uint8          【当前选中光标索引 Cursor Index (0..N)】
```

### 选项 ID 映射对照表：
* `0x00`: 继续游戏 (Continue) - 仅在存在存档时出现于列表顶部
* `0x01`: 从最初开始 (New Game)
* `0x02`: 不可思议的礼物 (Mystery Gift)
* `0x05`: Wi-Fi设定 (Wi-Fi Settings)
* `0x06`: 麦克风测试 (Mic Test)
* `0x08`: 合众连接 (Unova Link)

## 二、 角色动作与体态状态机标准 (结合 swan/field_player.h)

系统对玩家的体态进行了严密的双重特征融合识别：

```text
[Main RAM 0x0221F000: PlayerExState] + [Main RAM 0x0214362D: SubPixel Step]
                     ↓
┌─────────────────────────────────────────────────────────────┐
│ 状态判定输出 (Movement State)                               │
├─────────────────────────────────────────────────────────────┤
│ 1. Standing (静止站立)       : ExState=0, SubPixel=0x00/0x80│
│ 2. Walking (正常行走中)      : ExState=0, 步进值平缓切换    │
│ 3. Running (奔跑冲刺中)      : ExState=0, 步进值大跨度跳变  │
│ 4. Cycling (自行车骑行中)    : ExState=1, 处于骑行状态      │
│ 5. Cycling Idle (骑车停驻)   : ExState=1, SubPixel 静止     │
│ 6. Surfing (水面冲浪中)      : ExState=2, 冲浪移动          │
│ 7. Surfing Idle (水面浮水)   : ExState=2, 冲浪静止          │
```

## 三、 大地图矩阵 (Matrix #0) 连续空间拓扑换算公式

在宝可梦《黑2》合众大地图户外世界矩阵（Matrix #0，尺寸 $29 \times 27$ 分块）中，世界坐标完全连续，每个 Chunk 为 $32 \times 32$ 瓦片：

$$\text{Matrix Chunk X} = \lfloor \text{Global X} / 32 \rfloor, \quad \text{Local Tile X} = \text{Global X} \bmod 32$$
$$\text{Matrix Chunk Y} = \lfloor \text{Global Y} / 32 \rfloor, \quad \text{Local Tile Y} = \text{Global Y} \bmod 32$$

### 实测大地图分块拓扑图：
```text

                                                            ↕ (南北纵向无缝)
[ Chunk (1, 21): 模型 #281 ] <---> [ Chunk (2, 21): 模型 #282 19号道路 ] <---> [ Chunk (3, 21): 模型 #283 算木镇 ]
              ↕ (西南对接)
[ Chunk (1, 22): 模型 #280 桧扇市 (Aspertia City) ]
```

## 五、 文本系统与消息类型分类规范 (结合 SWAN / strbuf.c)

在游戏运行时的文本打印缓冲区 (`0x022490A0`) 与动态光标指针 (`0x0233605C` / `0x02333C74`) 中，系统将消息清晰划分为三类：

### 1. NPC 剧情对话消息 (`MSG_TALK` / `MAIN_NPC`)
* **特征**：由具体角色（如妈妈、白露、黑连、修、城镇居民）说出的对白，句子以 `[0x000A]` 开头，末尾由 `[0xF000][0xBE01]` 控制翻页。
* **时序与光标**：光标指针 `0x0233605C` 会随着玩家按下 A 键逐句前移（如：`怎么了？` ➔ `呵！宝可梦图鉴……要给我的孩子？` ➔ `很好啊！我也很希望那孩子能出发旅行！`）。

### 2. 官方与系统通知消息 (`MSG_SIGN` / `MSG_INFO` / `SYSTEM`)
* **特征**：获得道具、保存游戏记录、宝可梦升级、设施提示、路牌指示牌。无对话发言人，直接作为系统状态反馈。

### 3. 交互分支选项消息 (`MSG_YESNO` / `MSG_SELECT` / `PROMPT`)
* **特征**：句子以问号（`？` / `0xFF1F`）结尾，同时底层激活选项捕获，提供「是 / 否」或多项列表选择。

## 六、 动态对象与摄像机渲染管线 (`0x02279000 ~ 0x02279400`)

通过在真实运行帧中对主角静止时的 NPC / 摄像机运动捕获，我们定位并逆向了 **`field_camera.c`** 核心结构体：

### 1. 摄像机跟踪目标与视口平滑器 (`0x02279340`)
```text
偏移量 (Offset)     长度 (Size)     数据类型      物理含义与逆向结论
---------------------------------------------------------------------------------------------
+0x00 ~ +0x0F      16 字节         header/ptr    对象链头与链表指针 (指向 0x022792C0)
+0x10 ~ +0x1F      16 字节         ASCII string  源文件符号: "field_camera.c\0"
+0x20 ~ +0x27      8 字节          fixed-point   摄像机焦距与 FOV 视锥参数
+0x28 ~ +0x2B      4 字节          uint32        活动观察者序号 (Viewer Index = 7)
+0x2C ~ +0x2F      4 字节          uint32 (LE)   【当前跟踪视口目标 / 动态实体 ID】
+0x30 ~ +0x33      4 字节          uint32 (LE)   【动态实体当前动作相位 / 帧动画计数器 (Frame Phase 0..6)】
```

### 2. 实测 NPC / 场景动态实体分析记录
* **现象**：主角在台阶上保持静止，但 `0x02279340+0x2C` 与 `+0x30` 在 `[0, 1, 2, 3, 4, 5, 6]` 之间产生连续周期的状态转换。
* **物理意义**：
  * `+0x2C`：代表当前被摄像机视口跟踪的**场景动态对象 ID（如巡逻 NPC、野生宝可梦摇草/动态装饰物）**；
  * `+0x30`：代表该对象的**动画步进相位（Walk Cycle Phase: 0 -> 1 -> 2 -> 3 -> 4 -> 5 -> 6 -> 0）**。
  * 这是我们捕获到的第一个**真正的实机动态 Object / NPC 运行时对象**！
