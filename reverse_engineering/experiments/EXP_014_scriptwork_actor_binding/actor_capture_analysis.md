# EXP_014 子分析：ScriptWork → Actor 候选绑定

本文件仅重分析 `a_edge_capture_overlap_to_dialogue_end.json` 的同帧 RAM
抓包；没有读取新内存、按键、写 RAM，亦没有修改 Runtime 业务代码。

## 抓包范围与时间边界

- 样本：`before_edge` 至 `after_frame_64`，共 65 帧。
- 对话仍活动的最后一帧：`3584655` (`after_frame_14`)。
- 对话结束的第一帧：`3584656` (`after_frame_15`)。
- `0x02247546`：`01 → 00` 正好发生在上述边界。

三个本分析涉及的范围并非彼此独立：

| Artifact range | Main RAM absolute range | 关系 |
| --- | --- | --- |
| `script_work_context` | `0x02247300..0x022478FF` | 含活动 ScriptWork 周围的调试堆块。 |
| `script_actor_candidate` | `0x0223DC00..0x0223E1FF` | 含 `0x0223DCE4` 及其相邻候选槽。 |
| `former_player_candidate` | `0x0223DE00..0x0223DFFF` | 前一范围的严格子区，不能作为独立观测。 |

## 活动 ScriptWork 区在结束边界的变化

`f3584655 → f3584656` 时，以下原始值变化：

## `0x0223DCE4` 的 FieldActor 结构相干性

下表使用 SWAN FieldActor 偏移作为**待验证布局假设**，读取的是活动末帧
`f3584655` 的字节：

| SWAN hypothesis field | Offset | Observed value |
| --- | ---: | --- |
| `ActorUID` | `+0x08` | `u16 4` |
| `SCRID` | `+0x14` | `u16 13` |
| `FaceDir` | `+0x18` | `u16 0` |
| `MotionDir` | `+0x1A` | `u16 1` |
| `GPos` | `+0x3C` | `{u16 39, s16 1, u16 764}` |
| `WPos` | `+0x44` | `{0x00278000, 0x0001000F, 0x02FC8000}` |
| `m_ActorSystem` | `+0x88` | `0x0223DB68` |

X/Z 的整数关系尤其强：

```text
0x00278000 = 39  * 0x10000 + 0x8000
0x02FC8000 = 764 * 0x10000 + 0x8000
```

即以该候选布局解释时，`WPos.X/Z` 恰好是 `GPos.X/Z` 的格中心固定点
坐标。Y 的 `0x0001000F` 也接近对应 grid 层的基准，但本分析不赋予其
具体单位或高度语义。

此外，`0x0223DC6C, DD6C, DE6C, DF6C, E06C, E16C` 六处都保存
`0x0223DB68`，严格相隔 `0x100`。其中 `0x0223DD6C` 正是
`0x0223DCE4 + 0x88`。从 `0x0223DCE4` 起每 `0x100` 字节解析到的五个
完整槽也都呈现不同 UID/SCRID/GPos/WPos、相同 `+0x88` 回链：

| Slot address | UID | SCRID | GPos | `m_ActorSystem` |
| --- | ---: | ---: | --- | --- |
| `0x0223DCE4` | 4 | 13 | `(39, 1, 764)` | `0x0223DB68` |
| `0x0223DDE4` | 5 | 12 | `(55, 1, 749)` | `0x0223DB68` |
| `0x0223DEE4` | 6 | 11 | `(36, 1, 741)` | `0x0223DB68` |
| `0x0223DFE4` | 8 | 7000 | `(61, 1, 765)` | `0x0223DB68` |
| `0x0223E0E4` | 9 | 26 | `(59, 1, 737)` | `0x0223DB68` |

这构成跨字段、跨相邻槽、跨位置表示的一致性证据。结论为
`0x0223DCE4 = probable FieldActor`，不是 `verified`：尚未读取
`0x0223DB68` 验证 ActorHeap/Count/Field 回链，也未完成移动、转向和
不同 actor 的行为指纹实验。

它更不能直接等同 `speaker_actor`。活跃 ScriptWork 对它有一个直接
u32 引用，只能给出 `script_actor_candidate`；该字段可能代表 parent、
interaction target 或 message actor 中的任一种，必须经当前 ROM 的
消费者/命令语义验证。

## Actor 变化与重叠窗口

在终止边界，宽 actor 区只变动两个字节：

```text
0x0223DE7A: 0x20 -> 0x1F
0x0223E17A: 0x20 -> 0x1F
```

它们分别相对 `0x0223DCE4` 为 `+0x196` 与 `+0x496`，即若 `0x100`
stride 假设成立，则分别是相邻槽 `+0x96` 的同一未知字段。后续帧每两帧
继续同步递减，故只能标为未知计数/状态；不能命名为动作、朝向或说话状态。

`former_player_candidate` 的唯一终止变化是第一个地址
`0x0223DE7A`，因为它正好覆盖 wider `script_actor_candidate` 中的同一
字节。这次抓包没有产生任何独立的 Player 证据。

`0x0223DCE4` 自身的前 `0x100` 字节在终止边界没有变化。按 A 后第
14 帧之前曾观察到其 `+0x04` 从 `0x0A` 变为 `0x02`，并同样出现在每个
相邻槽；其语义未知，不能用于 actor 身份判断。

## 最小下一步：闭合 ActorSystem 关系

该实验目录随后保存的两个只读全 Main-RAM 指针扫描并非同一条 A-edge
抓包（它们的 bridge frame 分别为 `4194692` 与 `4194729`），故不能回填为
`f3584655` 的同帧事实；它们只提供下一轮的定位线索：

```text
target 0x0223DB68 -> reference at 0x0223B718
target 0x0223DCE4 -> references at 0x02247594, 0x02308708, 0x0230AEE4
```

按 SWAN `Field.m_ActorSystem = +0x40` 假设，第一条反推出一个更小的
`Field` 候选 `0x0223B6D8`。因此在新的、`script_msg_active = 1` 的同帧
批量读中，先读取这两个小块：

```text
Main RAM 0x0223B6D8, length 0xA0
Main RAM 0x0223DB68, length 0x80
```

只按 SWAN 假设检查（不预先写入 API）：

```text
Field +0x04:       GameSystem backlink
Field +0x28:       MsgBGSys candidate
Field +0x40:       ActorSystem pointer (must equal 0x0223DB68)
Field +0x94:       FieldPlayer candidate

+0x04 / +0x06: ActorCapacity / ActorCount (u16)
+0x1C:          ActorHeap pointer
+0x40:          Field backlink
```

若 `ActorHeap` 的 live 值落在当前 `0x100` stride 槽列，第二批才以该
动态指针读 `ActorCount * 0x100`（记录上限与实际长度），确认
`0x0223DCE4` 真正属于堆。随后从动态 `Field` 指针读取 `0xA0` 字节，验证
`m_ActorSystem (+0x40)` 回链和 `m_Player (+0x94)`。这是比全 Main-RAM
扫描更小、且能形成 `Field -> ActorSystem -> ActorHeap -> FieldActor`
闭环的下一轮。

若上述重读不再保持这些值，才在**该活动帧**重做对齐 u32 的全 Main-RAM
指针搜索，目标依次为 `0x0223DB68` 与 `0x0223DCE4`；对每个命中只扩读
`±0x80`。不要扫描/发布任何过期 ScriptWork 残留。
